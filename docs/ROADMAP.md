# Chimerazer — дорожная карта

Статус: черновик на согласование. Основа: исследование OpenSnek, OpenRazer и Snakecharmer (октябрь 2026).

## Цель первого этапа

Razer Naga Pro (`1532:008F` по проводу, `1532:0090` через свисток) полностью настраивается из Linux. Настройки записываются в память мыши и работают без запущенного приложения.

## Что берём и откуда

| Источник | Лицензия | Что берём |
|---|---|---|
| OpenSnek (Swift, macOS) | Apache-2.0 | Основа протокола Naga Pro: DPI, ремап всех 30 слотов, 5 onboard-профилей, захваты USB. Можно портировать логику с сохранением `NOTICE`. |
| OpenRazer (C/Python) | GPL-2.0 | Только факты: формат репорта, PID, wIndex, задержки, эффекты подсветки, данные BW V3 Mini. Код не переносим. |
| Snakecharmer (Rust, Windows) | GPL-2.0+ | Только факты и идеи: таблица устройств в виде данных, safety-latch, тесты на уровне байтов, инструменты захвата. Код не переносим. |

**Важно.** Поддержка Naga Pro в OpenSnek проверена контрибьюторами, а не мейнтейнерами, и все захваты сняты через свисток (`0x0090`). Провод не проверял никто. Поэтому наша мышь — это и есть валидация.

## Порядок работ

Правило: каждый следующий шаг опирается только на уже проверенный предыдущий. Элемент интерфейса появляется только для операции, которую уже проверили на железе.

### M0. Фундамент
- Cargo workspace, CI (fmt, clippy, тесты), udev-правило для доступа к hidraw без root.
- Таблица команд Naga Pro с источником каждой (`docs/protocol/`).
- Фикстуры из захватов OpenSnek для тестов парсера.

**Готово, когда:** CI зелёный, есть таблица команд и фикстуры.

### M1. Транспорт и только чтение
- Поиск устройства через udev, выбор интерфейса 0 (usage `0x01:0x02`, feature-репорт 90 байт).
- 90-байтный фрейм, CRC, статусы, сверка эха (txn, class, cmd, а также slot, profile и LED в аргументах).
- Чтение всего, что есть: серийник, прошивка, DPI и стадии, частота опроса, батарея, яркость, привязки всех 30 слотов, список профилей.
- **`dump`**: снимок всего читаемого состояния мыши в файл. Это **не** гарантированный бэкап: пока не доказано, что читается всё аппаратное состояние (особенно onboard-профили), `dump` фиксирует только то, что мы умеем читать.
- Нормализованная модель состояния: параметры мыши без транспортных метаданных (PID, интерфейс, txn, путь hidraw).
- CLI — первый функциональный интерфейс.
- **Не проверено до M1:** заголовок, CRC и transaction id ответов настоящей Naga Pro. Фикстуры M0 содержат только аргументы ответов. Первые сырые 90-байтные кадры — по проводу и через свисток — сохраняются в `fixtures/naga-pro/` (без серийного номера) и становятся тестами. Отдельно выясняется, какой txn нужен для `00:81` / `00:82`.
- Каждая команда чтения, отработавшая на нашем экземпляре с сохранёнными кадрами, получает статус `OurHardware`.

**Готово, когда:** нормализованное состояние совпадает по проводу и через свисток, повторный `dump` ничего не меняет, а разбор настоящих кадров (CRC, заголовок, эхо txn) покрыт тестами.

**Результат M1 (2026-10-29), на согласовании:**
- Все команды чтения, кроме `05:88`, — `OurHardware`; 98 сырых кадров с провода и свистка в `fixtures/naga-pro/our-hardware-frames.txt`, разбор CRC, заголовка и эха txn покрыт тестами.
- `chimerazer dump`: 235 значений, 0 ошибок, 228 обменов. Повторный дамп идентичен (провод и свисток), дамп по проводу идентичен дампу через свисток (без `volatile.*`).
- Открыто: `05:88` (метаданные профиля) отвечает `Failed` — к M5.

### M2. Безопасная запись
- Каждая команда записи впервые выполняется только через процедуру первичной аппаратной валидации (`docs/ARCHITECTURE.md`).
- DPI и стадии, частота опроса, статический цвет и яркость (колесо, логотип).
- Каждая запись делается по циклу: прочитать, записать, прочитать снова, сравнить.
- Для каждого параметра экспериментально выясняем, что переживает переподключение и перезагрузку, и фиксируем это в таблице.
- `restore` из `dump` — только для параметров, у которых доказаны полное чтение и обратная запись. Остальное `restore` явно пропускает и сообщает об этом.

**Готово, когда:** у каждого параметра M2 проверены запись, чтение и переподключение; `restore` возвращает эти параметры в исходное состояние.

**Ход M2 (2026-10-29):**
- Живой слой (`storage 0`) по проводу: DPI, стадии DPI, яркость логотипа и колеса — запись, чтение и возврат подтверждены, побочных изменений нет. DPI дополнительно подтверждён через свисток.
- Переподключение: значения живого слоя возвращаются к значениям активного профиля (живой слой — оперативная память).
- Профиль 1 (`storage 1`): DPI, стадии DPI, яркость логотипа и колеса записаны, подтверждены и **пережили переподключение**; запись в активный профиль сразу отражается в живом слое.
- Не проверено: выключение питания, сохранение через свисток, неактивные профили 2–4.
- Отложено владельцем: банк 5, частота опроса (`SourceOnly`), статический цвет.
- `restore` (`naga_pro::restore`, `chimerazer restore`) проверен на симуляторе и на нашем экземпляре по проводу: после `hold` (DPI 800, `active=2`, яркость логотипа 100 в профиле 1) `--dry-run` показал ровно 6 значений к восстановлению и ничего не записал; `restore` вернул 3 значения профиля 1, живой слой совпал сам (зеркало активного профиля); `diff` с исходным дампом — `identical (235 keys)` сразу и после переподключения. Не проверено: свисток, выключение питания.

### M3. Функциональная панель (GUI)
- Минимальный GUI поверх уже проверенных операций M1–M2. Дальше растёт вместе с ядром.

### M4. Переназначение кнопок
- Все 30 слотов: корпус, наклоны колеса, кнопка профиля, боковые панели на 2, 6 и 12 кнопок.
- Типы привязок: кнопка мыши, клавиша с модификаторами, DPI, переключение профиля, turbo.
- Сначала активный профиль, потом конкретный профиль по ID.

**Готово, когда:** каждый слот на каждой панели переназначен, проверен нажатием и пережил переподключение.

### M5. Onboard-профили
- Выбор, создание, удаление, запись содержимого в конкретный профиль.
- Самая рискованная часть, подробности ниже в разделе про риски.

**Готово, когда:** весь CRUD профилей работает, профили переключаются кнопкой на мыши, Synapse под Windows не считает их битыми, а `dump`/`restore` покрывают профили целиком (доказано сравнением до и после).

### M6. Стабилизация
- Проверочная матрица: все операции × провод и свисток × переподключение и перезагрузка × спящая мышь.
- Единый контракт операций, регрессионные тесты на фикстурах.

**Готово, когда:** выполнен критерий первого этапа из стратегии.

### M7. BlackWidow V3 Mini HyperSpeed (`0x0258` / `0x0271`)
- Подсветка (эффекты, кастомный кадр 5×16), яркость, батарея, LED игрового режима и макросов — по фактам OpenRazer.
- **Ремап клавиш — исследование, а не портирование.** Публичного протокола нет ни в одном из трёх проектов.

### M8. Полноценный UI
- Дизайн-система, UX. Только после M6.

## Риски и где можно буксануть

1. **Onboard-профили (M5)** — главный риск окирпичить настройки.
   - Метаданные профиля — 0xFA байт, пишутся четырьмя кусками. При частичной записи профиль портится (у Basilisk UUID превращался в 0xFF).
   - Поле владельца должно быть 64-hex хэшем, иначе Synapse считает профиль битым.
   - Последний кусок может не прийти с подтверждением, хотя записался.
   - Создание профиля сбивает DPI и яркость, а удаление не стирает данные, только убирает профиль из цикла переключения.
2. **Подтверждению нельзя верить.**
   - Naga Pro иногда отвечает ошибкой, хотя запись прошла.
   - Устаревший ответ может выглядеть как успех.
   - Отсюда два вывода: истиной считается только повторное чтение, и эхо сверяется полностью.
   - Модель Snakecharmer, где любая аномалия останавливает всё, слишком строгая для Naga Pro: при ошибке нужно перечитать и только потом решать.
3. **Неясно, что именно сохраняется в память.**
   - Для DPI источники расходятся: OpenRazer всегда пишет с флагом сохранения (VARSTORE), Snakecharmer без него, OpenSnek пишет таблицу стадий с флагом, а текущий DPI без.
   - Без экспериментов на M2 обещание «настроил и закрыл» ничем не подтверждено.
4. **Свисток и сон.**
   - Свисток остаётся в системе, когда мышь спит, и тогда команды отваливаются по таймауту.
   - Через свисток нужна задержка около 31 мс, по проводу хватает 0,6 мс.
   - Провод вообще не проверял никто.
5. **Конкуренция за устройство.** Если установлен OpenRazer, его драйвер шлёт команды в обход hidraw без всякой блокировки, и ответы перемешиваются. Нужны своя блокировка, обнаружение OpenRazer и предупреждение.
6. **Подсветка Naga Pro проверена не вся.** OpenSnek проверил только статический цвет и яркость. Эффекты и подсветка 12-кнопочной панели известны только из OpenRazer, а там есть неочевидная преамбула переключения режима и пометка `TODO: probably wrong`.
7. **Клавиатура отличается не только PID.** У неё интерфейс 3 вместо 0, txn `0x9F` через свисток и `0x1F` по проводу, есть разница сохранения между проводом и свистком. Значит, параметры транспорта должны задаваться на каждый PID, а не на модель. Это нужно заложить уже в M1, иначе на M7 придётся переделывать ядро.
8. **Противоречие в исходной стратегии.** В ней функциональный UI (этап 3) стоит раньше проверки (этап 4), то есть UI строился бы поверх непроверенных операций. В этой карте операция проверяется в ядре и CLI, и только потом получает элемент интерфейса.
