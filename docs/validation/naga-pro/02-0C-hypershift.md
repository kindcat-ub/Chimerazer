# HyperShift: включение и второй слой — Naga Pro, 2026-10-29

RZ01-0342, firmware 2.03, ресивер `1532:0090`, активный профиль 1.
Инструмент: `ac1df92` (путь записи из `6ca4959`), сборка в `chimerazer-dev`,
аппаратные команды на хосте. Запись разрешена владельцем для проверки HyperShift.
Серийник не сохраняется; прошивки и режим устройства не менялись.

## Источники и гипотеза

В закреплённом OpenSnek код включения HyperShift не найден: там есть чтение
и запись слоя и захваты другой модели без отдельного блока включателя.
Дополнительный источник фактов: OpenSynapse (MIT), commit
`1f16527fea6a9f6eeeba3ee714ad7ce6422edd5c`,
[`ViperObmProtocol.cs`](https://github.com/A1mAssist/OpenSynapse/blob/1f16527fea6a9f6eeeba3ee714ad7ce6422edd5c/src/OpenSynapse.Windows/Protocols/ViperObmProtocol.cs):
`ModeButtonKey = 12`, допустимые данные `[1]`. Это prior art для другой мыши,
не исходное доказательство для Naga Pro. Из этих фактов сформирован кандидат
семибайтного блока `0c 01 01 00 00 00 00`; чужой код не переносился.
Гипотеза: удержание такой кнопки включает слой `01` внутри самой Naga Pro.

## Ограниченный эксперимент

- Два свежих исходных дампа: 295 значений, 0 ошибок, совпали без `volatile.*`.
- Слот 2 (правая кнопка) исходно имеет флаг 1; его слой HyperShift заменён
  на `key:f8` (`02 02 00 41 00 00 00`). Обычный правый клик сохранён.
- Слот 3 (средняя) исходно имеет флаг 0; его обычный блок заменён на
  `raw:0c010100000000`. Его слой HyperShift не менялся.
- `hold` сначала записал то же значение и пробу слоя `01` слота 2,
  затем то же значение и пробу обычного слоя слота 3; оба чтения подтвердились.
- Свежий полный дамп показал ровно четыре ожидаемых изменения:
  `p1.button.02.hs`, `live.button.02.hs`, `p1.button.03`, `live.button.03`.
  Все флаги и прочие невольатильные значения сохранены.

Выбор слота с флагом 1 для пробы слоя `01` позволяет не менять его флаг
исследовательской записью слоя. Произвольные комбинации слоёв и флагов этим
экспериментом не проверялись. Использован существующий CLI с `raw:`, без новых
команд протокола, перебора кодов или отдельного программного переключателя слоёв.

## Проверка нажатием

Владелец выполнил: правая отдельно → средняя удерживается + правая → правая
после отпускания средней. Первоначальная запись содержит дополнительные клики
и удержание F8 с системным автоповтором, поэтому возврат к обычному действию
дополнительно проверен отдельным правым кликом без удержания любых кнопок.
В отдельной записи есть `BTN_RIGHT` (`273`) press/release, без F8.

После этого мышь полностью выключена на 10 секунд без кабеля, включена в
2.4 ГГц и разбужена движением. Дамп совпал с оставленными пробами: оба назначения,
флаги, остальные блоки второго слоя и прочее состояние сохранились.

Повтор после выключения дал чёткую последовательность:

1. Удержание средней + правая: F8 (`66`) press/release.
2. После отпускания средней правая отдельно: `BTN_RIGHT` (`273`) press/release.

Клавиатурные evdev-узлы ресивера перехвачены `EVIOCGRAB`, поэтому F8 не
доставлялась приложениям. Мышиные узлы читались без захвата для наблюдения
обычного правого клика. Диагностический Python-скрипт только читает evdev;
синтеза событий, демона переключения слоёв или Synapse нет. Захват после теста снят.

## Возврат и вывод

`finish` через ресивер: **PASSED: 2 value(s), persistence PASSED**.
Оба исходных блока возвращены; заключительный полный дамп — 295 значений,
0 ошибок, идентичен baseline без `volatile.*`. DPI и подсветка не менялись.

**Подтверждено:** `0c 01 01 00 00 00 00` включает HyperShift при удержании
средней кнопки; альтернативное назначение правой работает автономно, после
отпускания возвращается обычное действие. Обе записи в профиле 1 пережили полное
выключение. Подтверждение ограничено нашим экземпляром, ресивером, этими слотами
и флагами. Провод, прямая запись storage 0, другие активаторы/целевые слоты,
поведение при отпускании активатора раньше целевой кнопки не проверены.

Новый именованный вариант `hypershift` в кодек не добавлен: проба использует
имеющийся `raw:`. `02:0C` и `VERIFIED_WRITES` не повышались; M4 целиком не закрыт.

Локальные исходные материалы: `.artifacts/m4-hypershift/` (вне Git).
Сырые кадры ниже проверены: только `02:8C`/`02:0C`, без идентификаторов экземпляра.
