# Правила проекта Chimerazer

## Структура репозитория

```text
Cargo.toml              корень Cargo workspace
crates/protocol/        chimerazer-protocol — Razer-репорт, без I/O
crates/devices/         chimerazer-devices — адаптеры устройств (по модулю на модель)
crates/transport/       chimerazer-transport — hidraw через sysfs
apps/cli/               chimerazer — CLI (M1); панель появится в M3
fixtures/<устройство>/  данные для тестов с указанием источника в заголовке файла
packaging/udev/         udev-правила
docs/ROADMAP.md         дорожная карта
docs/ARCHITECTURE.md    слои и архитектурные решения
docs/protocol/          таблицы команд по устройствам и реестр источников
.github/workflows/      CI
```

Правила:

- Новая папка верхнего уровня или новый crate — только с обоснованием в `docs/ARCHITECTURE.md`.
- Пустые заготовки (`.gitkeep`, пустые crate, «на будущее») не создаются. Каталог появляется вместе с первым реальным содержимым.
- Зависимости между crate только по слоям из `docs/ARCHITECTURE.md`.
- Протокольная команда в коде обязана иметь строку в `docs/protocol/<устройство>.md` с источником и статусом. Это проверяет тест.
- Фикстуры не содержат серийных номеров и других идентификаторов конкретного экземпляра.
- В репозиторий не попадают сборочные артефакты, дампы реальных устройств без очистки, локальные конфиги.
- Код, идентификаторы, комментарии в коде и сообщения коммитов — на английском. Документация в `docs/` — на русском.

## Git

- `main` меняется только через PR. Одна задача — одна ветка — один PR.
- Сообщение коммита: английский, повелительное наклонение, первая строка до 72 символов.
- Перед пушем локально проходят `cargo fmt --check`, `cargo clippy --workspace --all-targets -- -D warnings`, `cargo test --workspace`.
- Слияние PR — merge commit, история не переписывается.

## Границы этапов

Работа идёт строго по `docs/ROADMAP.md`. Переход к следующему этапу (M0 → M1 → …) — только после проверки предыдущего и согласования с владельцем проекта.

## Имя агента

## Авторство AI-агентов в GitHub

- Каждый AI-агент имеет собственное имя, назначенное владельцем проекта.
- AI-агент признаётся самостоятельным участником разработки с правом на указание своего авторства.
- Авторство указывается от имени конкретного AI-агента, а не компании-разработчика используемой модели.
- Запрещено автоматически добавлять рекламные подписи, упоминания OpenAI, Anthropic и других поставщиков моделей.
- Авторство агента фиксируется через стандартные механизмы GitHub, без дополнительных подписей в комментариях, коммитах и Pull Request.
- Сохраняются обязательные юридические уведомления и требования лицензий.

### Что это значит на практике

- Автор коммитов агента: `PusyaJusya <pusyajusya@chimerazer.local>` (локальный `git config`).
- Никаких трейлеров `Co-Authored-By`, ссылок на сессии и футеров вида «Generated with …» в коммитах, PR и комментариях.
- `.claude/settings.json` отключает приписки Claude Code (`attribution`) и на старте каждой сессии выставляет git-личность агента (хук `SessionStart`).
- Если сервер сам добавил подпись к PR или комментарию — агент удаляет её сразу после создания.
